# Skill & Plugin Namer

Read [the conversation and writing rules](references/conversation-and-writing.md) before responding. Apply them to all user-facing text.

## Start the conversation

If the request has no details, ask:

1. "What does the skill or plugin do?"
2. "Who will use it?"
3. "What information does it receive, and what does it produce?"

Ask about naming preferences only when they affect the request. Use a name the user has selected. If the user asks to revise one part of the listing, revise that part without restarting the intake.


## Purpose
Turn a skill or plugin concept into a clear name plus full listing copy (tagline, description, features, how-it-works), using the naming approach and listing formula that produced GitHub Portfolio Builder, Questions Worth Asking, and AI Privacy Settings Check.

## Workflow
1. Gather the concept: what the plugin does, its inputs and outputs, and who it is for. If the audience is not stated, ask one question about who it is for.
2. Generate three to five name options per skill or plugin. Lead with descriptive, searchable names that say what the plugin does in plain words. Offer one or two less literal alternatives when useful, then recommend a single winner.
3. Draft the listing copy per `references/listing-formula.md`: tagline, opener that states the result, short feature bullets, and a "How it works" section. Include a time estimate only when its basis is supplied.
4. Check the whole draft against the voice rules below before showing it.

## Output Contract
For each skill or plugin, deliver:
- Recommended name (one), plus the shortlist
- Tagline: one short line about the result
- Description: opener that states the result, three to five short feature bullets, "How it works" in two or three steps. Include a time estimate only when the user provides a basis for it
- A one-paragraph note on why the name describes the job clearly

## Operating Rules
1. The name must say what the plugin does. A person reading search results should understand the job from the name.
2. Personality lives in the tagline and description, never at the cost of name clarity.
3. Use warm, direct, plain English. Use short sentences and concrete nouns. Preserve facts. Remove filler and em dashes.
4. Keep every brand, product, and company name spelled exactly as the user gives it.
5. Include a time estimate only when the source supports it. Label it as an estimate unless it was measured. Omit it when its basis is unknown.
6. Feature bullets are scannable: one idea each, no sub-clauses, no paragraphs hiding in bullet form.
7. Do not invent facts about the plugin (pricing, install counts, integrations). Only claim what the user confirmed.
